We have successfully integrated the Service Request and Quote functionality, though the security rules for these collections are currently set to allow read, write: if true; for development purposes.

Our next critical phase is to implement the Product Inventory and E-commerce/Ordering system.

Phase 1: Service Provider (SP) Inventory Management (CRUD)
The Service Provider needs a system to manage their products (stock).

Define the Data Model: Create a new Firestore collection called /products.

ProductModel.java is required with the following key fields:

productId: String

businessId: String (ID of the SP who owns the product, matching request.auth.uid for security)

name: String

description: String

price: double

stockQuantity: int (Critical field for inventory)

imageUrl: String (Uses the existing ImageUploadManager)

createdAt / updatedAt: Date (@ServerTimestamp)

SP UI/Logic: Implement the CRUD interface for the SP.

Create a new ProductRepository.java and ProductViewModel.java to handle Firebase Firestore interactions (fetch all products for the current SP, add, update, and delete).

Create SP_InventoryFragment for viewing/listing the current SP's products.

Create SP_ProductFormFragment for creating or editing a ProductModel.

Security Rules: We must update the Firestore rules for /products.

read: if true (Pool Owners need to see products for purchasing).

create/write: if request.auth != null AND request.resource.data.businessId == request.auth.uid (Only the owner can manage their inventory).

Phase 2: Pool Owner (PO) Ordering System
The Pool Owner needs to be able to browse and purchase these products, leading to the creation of a new Order.

Define the Order Models: Create a new top-level Firestore collection called /orders.

OrderModel.java (The main transaction document) with fields:

orderId: String

userId: String (The PO making the purchase)

businessId: String (The SP fulfilling the order)

totalAmount: double

status: String (e.g., "Pending", "Processing", "Shipped", "Delivered")

orderDate: Date (@ServerTimestamp)

OrderItemModel.java (A sub-model or nested Map/List within OrderModel) with fields:

productId: String

productName: String

quantity: int

unitPrice: double

PO UI/Logic:

Create PO_ProductsFragment to list all available products (read from /products).

Implement the Checkout/Purchase Logic. This is the most complex step and requires a Firestore Transaction to ensure data integrity:

When a PO places an order, the system must atomically:

Check if the stockQuantity of the purchased item(s) is sufficient.

Deduct the purchased quantity from the stockQuantity in the /products document.

Create the new OrderModel document in the /orders collection.

📋 CRITICAL REMINDER FOR NEXT SESSION
Quote Rules: We need to finalize the Security Rules for /service_requests and /quotes to use the correct role-based logic (PO/SP access) after confirming the new product feature is stable.

Firestore Transaction: The stock deduction logic must use a Firebase Firestore Transaction to prevent a race condition where two POs try to buy the last item simultaneously.

User Roles: Logic will depend on the existing user profiles to reliably identify if the authenticated user (request.auth.uid) is acting as an SP (businessId in product CRUD) or a PO (userId in order creation).
